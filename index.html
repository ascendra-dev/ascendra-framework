What this actually is

Not a platform. Not a SaaS tool.

Ascendra is a structured set of documents, templates, standards, and slash commands that you run locally inside Claude Code. There's nothing to install, host, or subscribe to beyond Claude itself.

AI generates each artifact — the brief, the requirements document, the architecture, the code. You review it, correct it where it's wrong or shallow, and approve it before the next step is allowed to start. Nothing moves forward on its own.

It doesn't replace a skilled Product Owner. It replaces the team a skilled PO would otherwise need to hand work off to — business analyst, solution architect, engineers, QA — by putting that range of thinking in one place: you, plus Claude, working through the same structured sequence a whole team would otherwise follow.

Core philosophy

Five rules the whole framework follows

01

One PO + AI beats a team doing handoffs

Every handoff between a BA, an architect, and an engineer loses context. Keeping one accountable person across the whole sequence doesn't.

02

Every artifact is reviewed before the next step starts

AI writes the draft. Nothing is treated as done — or read by the next command — until you've said so.

03

One shared vocabulary, from day one

A term defined in the domain glossary is binding everywhere after — code, database, API, conversation. Synonyms don't get to drift in.

04

Technology-agnostic by design

Each project confirms its own stack in its own standards. Nothing here mandates a framework, a language, or a hosting provider.

05

A project is one user-facing purpose

A web app and its API are one project. A teacher portal and a parent portal are two — even sharing one backend.

Who it's for

A force multiplier, not a teaching tool

This amplifies delivery skill you already have. It doesn't hand you skill you don't.

✓ Good fit

  • You've delivered software end to end before, including client-facing discovery
  • You can read an AI-generated BRD or architecture doc and tell when it's wrong or shallow
  • You know what a domain model is and what an architecture decision actually costs
  • You want to run one project properly, or several at once, without growing a team

⚠ Not yet a fit

  • You're looking for the AI to make product or architecture judgment calls for you
  • You haven't run a real requirements discovery session with a client before
  • You'd rather skip the review gates than slow down to check the AI's work
  • You expect a running product out of the box, rather than a delivery process you drive

Get started

From clone to your first brief

# 1. Clone the framework git clone https://github.com/zakashah/ascendra-framework cd ascendra-framework # 2. Open this folder as your Claude Code session root # (slash commands only load from the active root) # 3. Create your first project /init-project # 4. Complete the project brief /run-intake # 5. Start discovery /run-brd-discovery
  • Install Claude Code and clone the repoYou need Claude Code and an Anthropic subscription with Claude access — nothing else to install.
  • Open the repo root as your sessionEvery slash command loads from the active root directory, so this has to be it.
  • Run /init-projectCreates projects/{CODE}/ with every folder the pipeline expects.
  • Work the brief, then the sequenceEvery phase after this is its own command, reviewed and approved by you before the next one runs.
Solo by default. projects/* is gitignored — your client work stays local automatically. Running with a team sharing one project workspace needs its own setup; see the README.
