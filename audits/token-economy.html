    Cross-cutting findings

    The framework already had real, deliberate token-economy design in several places before this audit — and a handful of genuine, now-fixed inconsistencies where the same discipline wasn't extended. Read these before the phase tables below; most per-command verdicts point back here.

    ✓ Patterns already worth keeping

    anchor-project · Step 3 "Read lightly, not fully… use a targeted search rather than loading a whole BRD or architecture document into context to answer a one-field question." The clearest economy mission-statement in the framework — and it tiers drift checks into free / cheap / heavy-on-trigger, never running the expensive ones by default.
    judgment-check · Step 3 "Read exactly three files, nothing more." Explicitly refuses to follow chapter cross-references or sibling artifacts unless one specific test depends on it — the most disciplined single-invocation footprint of any command.
    assess-change · Step 1 The only command with a hard, stated ceiling: never more than 5 epic files or 15 story files in one session — split the session if the blast radius exceeds it. Everyone else audits reads qualitatively; this one puts a number on it.
    arch-v1-ref.md pattern gen-story-plan, implement-story, verify-story all read a condensed architecture reference first and only fall back to the full document for specific, named gaps — with an explicit rule against silently skipping the disclosure when they do fall back. Extended to the BRD via brd-core-v{N}-ref.md (FW-052) since this pass.
    review-epics / review-stories Three-tier loading: shared context once, then the current epic only, then the current story only — never all epics or all stories at once, even across a very long review session.
    implement-story · Standards Self-Check Deliberately re-reads every relevant standards file a second time before finishing, "not from memory of what was written earlier in this same session" — the framework's own explicit acknowledgment that recalled rules degrade over a long session, mitigated by forcing a re-read instead of trusting recall.
    run-priming-session / -code-session Map → triage → extract, checkpointed per file or per code unit, explicitly built so "one file can take more than one session" and the code variant "never reads the full repository" at all.

    Gaps found — status since first pass

    gen-stories fixed Re-read the full BRD and referenced domain docs on every per-epic invocation with no reuse caveat, one line below an identical exemption already granted to estimation.md. Both reads now prefer brd-core-v{N}-ref.md and carry the same-session reuse note.
    gen-architecture / review-architecture fixed (partial) Both mandated reading every file in standards/ with no ceiling. On reflection, gen-architecture genuinely needs the full set to write Sections 4–6 in one pass — a cap there would be a fix in search of a problem, so it was left as-is. review-architecture's resumed-session read is now scoped to the concern being resumed instead of reloading everything.
    No BRD-equivalent of arch-v1-ref.md fixed Six-plus commands each independently did a full-BRD read for REQ-level planning. brd-core-v{N}-ref.md (FW-052) now covers that — generated by /review-brd on approval, kept in sync by /assess-change.
    review-architecture per-resume reload fixed Folded into the fix above — Section 12 already tracked which Concern was pending; the standards read is now scoped to match it.
    gen-architecture — lost-in-the-middle risk documented No structural fix exists short of the cite-don't-restate discipline it already uses. The command now states outright that it should run in a dedicated, otherwise-empty session — turning the audit's recommendation into a load-bearing instruction rather than leaving it as an external note.
    Session-mode heuristic used throughout this audit — chain two commands in one session when the downstream one needs the exact document the upstream one just produced or discussed, and the upstream session wasn't itself a long, heavily interactive one. Prefer a fresh session when the upstream command accumulated a lot of confirmation-gate dialogue that has no value to the next task (that dialogue is real token weight, not just the documents), when the two steps are naturally done by different people or on different days, or when parallel/team execution requires independent sessions by construction (implement-story, verify-story, gen-pr-description are safe to run in parallel precisely because each touches only its own story's files).
